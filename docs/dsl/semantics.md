# Семантика TextCAD DSL v0

## Source-first модель

Текст документа является источником истины. AST, дерево, геометрия и mesh можно
полностью восстановить из него. Сериализованный mesh не является частью v0-файла.

## Выполнение

Документ выполняется сверху вниз.

```text
[let profile ...]
[let body [extrude profile length=20mm]]
[root body]
```

Ссылка может указывать только на ранее объявленное значение. Forward references
и циклические зависимости в v0 запрещены.

## Значения и неизменяемость

`let` связывает имя с вычисленным значением один раз:

```text
[let base [extrude baseProfile length=8mm]]
```

- повторное объявление `base` является ошибкой;
- CAD-операции не изменяют входное значение;
- `cut base holes` создаёт новый shape;
- неизменяемость делает историю операций воспроизводимой.

## Параметры

`param` создаёт именованное скалярное значение:

```text
[param width 100mm]
[param angle 45deg]
```

В v0 параметр может содержать число или физическую величину. Выражения над
параметрами планируются после первой реализации parser/evaluator.

## Система координат

- правая система координат;
- ось Z направлена вверх;
- базовые плоскости: `XY`, `XZ`, `YZ`;
- положительное направление extrusion совпадает с нормалью плоскости;
- точки sketch задаются в локальных двумерных координатах плоскости.
- `origin=[x y z]` у `sketch` задаётся в мировых координатах и по умолчанию равен нулю;
- нормали базовых плоскостей: XY — +Z, XZ — -Y, YZ — +X.

## Sketch и profile

`sketch` определяет плоскость, а `profile` — замкнутую область на ней.

```text
[sketch plane=XY
  [profile role=outer
    [line start=[0mm 0mm] end=[40mm 0mm]]
    [line start=[40mm 0mm] end=[40mm 20mm]]
    [line start=[40mm 20mm] end=[0mm 20mm]]
    [line start=[0mm 20mm] end=[0mm 0mm]]
  ]
]
```

Правила v0:

- первый и последний сегменты должны образовывать замкнутую цепь;
- соседние сегменты должны совпадать концами в пределах tolerance;
- самопересечение outer profile является ошибкой;
- `role=outer` задаёт внешнюю границу;
- `role=hole` задаёт отверстие;
- circle является самостоятельно замкнутой кривой;
- как минимум один outer profile обязателен.

Начальная реализация может поддерживать один outer profile, но AST и
спецификация допускают несколько profiles, чтобы не менять формат позже.

## Roots

`root` публикует значение как результат документа:

```text
[root body label="Main body"]
```

Документ обязан иметь хотя бы один root. Все уникальные опубликованные roots
отображаются во Viewport одновременно. Объединение отображаемых треугольников
не является булевым объединением: для объединения объёмов одной детали явно
используйте `union`. Один root может содержать несколько несвязанных тел.

## Булевы операции

`union`, `cut`, `intersect` принимают 2–32 тела по ссылкам или вложенные операции.
Выполнение идёт слева направо. Входные объекты сохраняются; результат — новое значение.
Проверяется наличие объёмных тел и корректность топологии OpenCascade.
Пустые результаты возвращают диагностику и не заменяют последнюю успешную модель.

## Вращение и круговой массив

`revolve` вращает эскиз вокруг мировой оси; замкнутое радиальное сечение в XZ
и ось Z дают осесимметричное тело. `pattern-circular` повторяет тело вокруг
мировой оси. В обоих случаях `axis` задаёт направление, `origin` — точку оси;
они не зависят от начала координат входного эскиза. По умолчанию это ось Z через
мировой ноль.

Углы принимают `deg`, параметры углов или числа в единицах заголовка. Количество
экземпляров безразмерно и ограничено 1–128. Полный круг не дублирует конечное
положение, частичный диапазон включает оба конца. Перекрывающиеся экземпляры
объединяются; исходное тело сохраняется. Правила аргументов — в `commands.md`.

## Ревизии и конкурентное выполнение

Каждый запуск получает монотонный `revisionId`.

1. Source изменяется.
2. Parser создаёт AST и diagnostics для новой ревизии.
3. При отсутствии parse errors запускается evaluator.
4. Результат применяется только если его `revisionId` всё ещё актуален.
5. Устаревший результат игнорируется.

Это необходимо для будущего выполнения Replicad в Web Worker.

## Artifact graph

Evaluator возвращает связь между представлениями модели:

```text
AST node
  ↔ source span
  ↔ declared value
  ↔ Replicad shape
  ↔ feature-tree node
  ↔ Three.js object
```

Node ID действует только внутри одной ревизии. Имена, объявленные через `let`,
являются стабильными пользовательскими ссылками.

## Ошибки

Parse или semantic error не заменяет последнюю успешно построенную геометрию.
UI показывает ошибку и помечает текущий Source как не синхронизированный с
отображаемой моделью. Подробности определены в [diagnostics.md](diagnostics.md).
